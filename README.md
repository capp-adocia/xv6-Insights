# xv6-启动阶段

## boot启动

1. 先看bootasm.S文件，这个文件是计算机上电加载的第一个代码，bios会从磁盘的0柱面0磁道1扇区读取这个代码，然后运行到物理地址0x7c000处，刚开始这个其实处在实模式又叫实地址模式即只能使用16位的地址空间，这个看起来让人一头雾水，有人可能会疑问为什么直接加载32位呢，这其实算是历史遗留问题，由于8086开创了先河，很多机器上启动都要兼容8086，那么没有办法，后续开发的cpu都是向前兼容的，于是现代的计算机启动都无法避免先进入实模式，再进入保护模式（32位/64位），虽然很麻烦，但这是开发os必经之路，容不得半点马虎，所以这份代码就是先从实模式->保护模式，随后调用bootmain.c中的bootmain()。这里从实模式跳转到保护模式还有一些必备工作要做，第一步先关中断，防止被bios中断干扰跳转；第二步开启A20,这个也是历史遗留问题，感兴趣的可以查查wiki；第三步就是加载gdt描述符，这个gdt表是预先在数据段中做的也可以边执行边做，前一种更简单方便，xv6就是前者，gdt比较复杂字段比较多，不一一说明了，简单说说吧，从分段和分页寻址方式讲起吧，分段模式，这个主要用于实模式，现代保护模式几乎不用了，都在用分页，分段寻址有cs和ip，cs存放段寄存器，而ip就是相对偏移量，比如cs=0x1000,ip=3;那么最后的地址就是0x10003,这样尽管看上去只能访问16位空间，实际能访问的20位。这里gdt表发挥了作用，把gdt表看成是一个结构体数组，结构体中指明了该段是代码段还是数据段，它的地址又是从哪里到哪里到哪里，权限又是什么等等设置，这些信息为我们以后分页做好了准备。xv6这里就设置了3个表项，第一个默认为null，后面两个就是代码段和数据段了，还有一个gdt描述符，这其实就是指向gdt表的结构体，存了gdt表地址和界限，然后我们才汇编指令中使用lgdt这个命令来加载这个gdt描述符，从而得到这些表项的信息，对cpu来说这就是一个地图，标清了各个”藏宝点“的位置等信息。这还不算完，最后设置cr0保护模式使能位为1,再跳转到32位的代码这才完成了从实模式到保护模式的飞跃。

2. bootmain.c文件是用来读取c内核的，为什么要现在读，不在实模式读，这里就要提到实模式的限制了，实模式下只能访问16位的地址空间，尽管实际可以利用偏移4位来访问20位的空间，但不够自由，而xv6似乎将用户空间放在底地址，而内核放在高地址处0x80000000,在后面我们就能看到了，bootmain()解析存储在磁盘上的os内核文件，这个文件称为elf文件，可以简单类比为windows上的exe文件，exe文件有相应的文件头来标明当前文件类型，同样，elf也有，所以需要读入这个文件检查是否符合我们想要的elf文件格式，然后读取下一个运行的函数地址，跳转执行，在这里应该跳转到entry.S这个入口函数了。

3. xv6内存布局，xv6在entry.S中先开启了分页功能，这里是为了将内核代码加载到虚拟空间的0x80100000，而实际上内核代码在1MB位置处，这里的0x80100000实际上是由链接器决定的，而实际加载的地址也写到了链接器中是0x100000，相对偏移了0x8000000，还有这里把开启分页前设置了一个双重映射即把0x0到...4MB大小空间映射到了0x0到...4MB地址空间，把0x8000000到...4MB大小空间映射到了0x0到...4MB大小空间，刚开始读不理解，这里不是保留高地址映射不就好了吗，为什么多此一举，实际上这是为了保证接下来运行的指令正常运行设计的，因为一旦开启分页后，立马就用虚实转换了，此时你没有把原来的地址映射那么比如会导致缺页异常，所以我们必须先用临时页表开启双重映射，设置完成后，就可以开始跳转到main函数了。

4. 看entry.S这个文件所在的目录，你很容易找到下面和它很像的文件名为entryother.S这个文件，凭我们的直觉它是多余的吗？这个问题在我们继续研读下去，将会揭晓答案。entry.S设置了一些寄存器，比如cr0、cr4等等，这些是初始化它们的状态的，这里xv6是提前分页了，所以要设置这些标志位，最后跳转到main.c的入口函数，此时我们终于不用再看令人抓狂的汇编的，尽管接触汇编快有半年多了，到现在还是看着难受，还是c香。话不多说了，让我们看看c内核咋写的吧，相信比起之前要好读不少哈。最后吐槽一句，xv6的c代码风格是真不适应，写个函数还把返回类型和函数名换行分开，看的着实别扭。

## xv6-进入c内核

1. main.c文件是做一些初始化的，比如中断向量初始化、进程初始化等等，做完了这些初始化工作后，main()中有一个startothers()，xv6解释说是启动其他的非引导AP处理器，这里“非引导”大概猜测系统启动流程是先让一个cpu跑起来，进入引导程序，引导到main函数。

## xv6-kinit1

1. kinit1接受两个参数,代表要释放的范围,第一个参数是内核结束的地址,第二个参数是4MB位置处,然后把这些空闲的空间都加入到空闲单链表中.当时我很疑惑,为什么不一开始就初始化全部内存呢,而是先初始化一小部分后,再初始化后续的,说到这里,当我看完第二个函数kvmalloc的功能后才明白,这里释放的空间是用来存放页表的,而有了页表才能初始化更大的空间,这是由我们一开始在entry.S中决定的,当时使用了4MB大页,设置的是4MB的范围,所以我们只能访问到4MB.

## xv6-kvmalloc

1. 正如之前所说这个是用来初始化内核页表的.这个函数干了两件事:第一,创建页目录,设置页表;第二,切换新的cr3页目录基地寄存器

2. 这里必须要介绍的是i386中引入的二级分页，这是虚拟内存中最为重要的知识之一，请务必理解，这里我摘取了xv6中mmu.h虚拟地址表示：
```
 +--------10------+-------10-------+---------12----------+
 | Page Directory |   Page Table   | Offset within Page  |
 |      Index     |      Index     |                     |
 +----------------+----------------+---------------------+
  \--- PDX(va) --/ \--- PTX(va) --/
```
我们可以看出高10位代表的是页目录索引，中间10位代表页表索引，低12位代表页内偏移，再逐一说说页目录、页表里的是存放的是什么，首先页目录中每一个条目叫做页目录项，同理，我们也可以说页表中每一个条目是页表项，页目录中每一个页目录项里面存放的是32位数，其中高22位代表的是页表的物理地址，而低10位代表的是标志位；而页表项中高22位代表的是物理页对应的物理地址，低10位是标志位。我们再来说说cpu具体如何通过虚拟地址来获取实地址的，转换流程：cpu先去内存中取指令，取指令需要找到指令的地址，也就是找PC里对应的值，然而PC里对应的值是虚拟地址，因此我们必须要转换为物理地址才能正确找到，它首先取出32位中的高10位页目录索引，再读出cr3页目录基址寄存器，通过公式： 页表物理地址 = （cr3 + 页目录索引*页目录项大小）>> 10，这样就获取了页表的物理地址了，接下来我们要获取物理页所在的地址，也是类似的方法，我们再次对虚拟地址取中间的10位页表索引，公式：物理页地址 = (页表物理地址 + 页表索引 *页表项大小) >> 10,这样我们就获取了物理页的所在的位置了，但这还不能完全找到指令的地址，因为我们获取的只是该指令对应的页地址，不是指令的地址，所以我们需要再加上虚拟地址的低12位来得到最终的物理地址，至此，二级分页介绍完毕，这里注意的是这个过程不是由我们编码写的，而是硬件自动控制的，我们只需要填充数值即可。

3. 我们主要看第一件事.看setupkvm这个函数,它返回的是页目录的基地给全局变量kpgdir,在setupkvm中,先从空闲链表中,分配出一页,所以我们进入main要做的第一件事情其实就要把空闲链表初始化好,这就像我们盖楼,必须要要有地才能开始盖。这里分配完成后，后面一个for循环是对页目录项、页表项设置对应的值，其中walkpgdir是设置页目录项的值，而它会返回页表项的地址，后续我们对它解引用设置值。

## xv6-seginit

1. 这里设置的是gdt表，之前也说过相关的，这里gdt表有8B，第一个表默认填充0,从第二个开始才是我们要设置的段，这里设置了4个段，分别是内核代码段、内核数据段、用户代码段、用户数据段，还需要设置对于的权限，比如内核段DPL都是0,用户段都是3,这是必须的。

2. 这里还必须要介绍一下Ring0-3,其中Ring0代表最高权限，指代的是内核态，Ring3是最低权限，指代用户态，高权限要访问低权限是不会被约束的，但如果是Ring3访问Ring0，那么就不被允许，只能访问当前权限的数据或比当前权限低的数据。从而出现了CPL（当前权限）、DPL（描述符权限）、RPL（请求权限）。这里我举例说说具体cpu如何来检查的，比如用户态要访问内核段的数据，那么用户态的CPL=3,DPL=0,RPL=3，我们可以简单比较CPL和DPL的值就可以轻松判断这是不被允许的，但注意还有一种情况，那就是使用系统调用来访问内核态的数据，当通过系统调用进入内核态时，此时的CPL=0,DPL=0,RPL=3,这里不能再只看CPL和DPL的值了，还要加上RPL,这才是真正的请求源权限。所以这三个缺一不可。
